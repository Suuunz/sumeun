# 숨은 여행 (Hidden Travel) — PRD

> 잘 알려지지 않은 지역을, 지도 위에서 발견하고 코스로 만드는 국내 여행 서비스

---

## 1. Problem

### 1-1. 배경
국내 여행 검색은 **이미 유명한 지역에 극단적으로 쏠려 있다.** 포털·SNS·기존 여행 앱은 모두 "검색량 / 리뷰 수 / 예약 수" 기반으로 정렬되기 때문에, 데이터가 많은 곳이 더 노출되고 노출된 곳에 데이터가 더 쌓이는 구조다. 그 결과:

- 여행자는 매번 **같은 몇 개 지역**(제주·부산·강릉·경주)만 반복해서 소비한다.
- 실제로 관광 콘텐츠·먹거리·특산물이 충분한 중소 시군구는 **탐색 후보에조차 오르지 못한다.**
- 지역 입장에서는 공공데이터(TourAPI, 착한가격업소 등)로 정보를 공개해도 **닿을 채널이 없다.**

### 1-2. 사용자가 실제로 겪는 문제
| # | 문제 | 지금 사용자가 하는 행동 |
|---|---|---|
| P1 | **어디로 갈지**를 못 정한다. 목적지가 정해져야 검색이 시작되는데, 그 첫 단계에 도구가 없다 | "국내여행 추천" 검색 → 광고성 리스트 → 결국 유명지 선택 |
| P2 | 낯선 지역은 **정보가 파편화**되어 있다. 관광지는 A 사이트, 맛집은 블로그, 물가는 알 수 없음 | 탭 10개 열고 비교하다 포기 |
| P3 | **가격을 예측할 수 없다.** 낯선 곳일수록 바가지 우려가 커서 회피 요인이 된다 | 검증된(=유명한) 관광지로 회귀 |
| P4 | 정보를 모아도 **동선으로 묶는 일**은 전부 수작업이다 | 메모장 + 지도 앱 수동 조합 |

### 1-3. 핵심 문제 정의
> **"유명하지 않은 지역"은 정보가 없어서 안 가는 게 아니라, 정보가 흩어져 있고 탐색 진입점이 없어서 안 간다.**
> 공공데이터는 이미 존재한다. 없는 것은 **발견 경험(discovery UX)** 이다.

## 2. Target User

### 2-1. Primary Persona — "반복 여행에 지친 탐색형 여행자"
- **누구**: 20~30대, 연 3회 이상 국내 여행, 1~2인 또는 커플 여행
- **특징**: 갈 만한 데는 대충 다 가봤다는 감각. SNS에 안 나온 곳을 선호하지만 직접 발굴할 리서치 체력은 없음
- **Pain**: "새로운 데 가고 싶은데, 검색하면 늘 나오던 곳만 나온다"
- **Trigger**: 주말/연휴 2~3주 전, 목적지 미정 상태에서의 막연한 탐색

## 3. Solution Concept

### 3-1. 한 줄 정의
> **전국 시군구 단위 지도 위에서, 공공데이터로 지역을 "발견"하고 → 상세를 "탐색"하고 → 나만의 코스로 "완성"하는 서비스**

### 3-2. 설계 원칙 3가지
1. **목적지가 없는 상태에서 시작한다.**
   기존 서비스는 "안동 검색"부터 시작하지만, 우리는 **"어디로 갈까?"** 상태의 사용자를 첫 진입점으로 삼는다. → 취향 온보딩 + AI 추천 + 지도 클릭
2. **검색이 아니라 지도로 탐색한다.**
   리스트/랭킹은 유명지 쏠림을 재생산한다. 전국 시군구 폴리곤(TopoJSON) 지도를 기본 UI로 두어 **모든 지역이 동등한 크기의 진입점**을 갖게 한다.
3. **한 지역의 정보는 한 화면에 모은다.**
   관광지 / 먹거리 / 착한가격업소 / 특산물 / 추천 코스를 SIG_CD(시군구 코드) 하나로 조립해 단일 번들로 제공한다.

### 3-3. 데이터 기반 (모두 공공데이터, 실적재 완료)
| 데이터 | 출처 | 역할 |
|---|---|---|
| 관광지 / 음식점 / 여행코스 | 한국관광공사 TourAPI | 지역 콘텐츠 본문 |
| 착한가격업소 (업소·메뉴·가격) | 행정안전부 공개 데이터 | **가격 신뢰 근거** (차별화 포인트) |
| 지역 특산물 | 자체 시드 | 지역 정체성 |
| 시군구 경계 폴리곤 | SIG TopoJSON | 지도 인터랙션 기반 |

> 모든 데이터는 **SIG_CD(시군구 코드)를 조인 키**로 통일 — 서로 다른 출처의 데이터를 하나의 지역 화면으로 묶는 핵심 설계.

## 4. Core Features & Value

### F1. 취향 온보딩 (`/onboarding`)
- **무엇**: 2문항 선택 — ① 여행지 유형(이름난 곳 / 잘 안 알려진 곳) ② 분위기(북적이는 곳 / 잔잔한 곳). 건너뛰기 가능
- **가치**: 진입 마찰을 최소화하면서 추천의 초기 신호를 확보. "잘 안 알려진 곳" 선택 자체가 서비스의 정체성을 사용자에게 학습시킨다

### F2. 전국 시군구 탐색 지도 (`/map`) — **핵심 화면**
- **무엇**: TopoJSON 기반 전국 시군구 폴리곤. 지역 클릭 → 우측 슬라이드 패널에 요약(특산물 / 착한가격업소 / 추천 반일 코스)
- **가치**: 검색어를 몰라도 탐색이 시작된다. 랭킹 없는 **평평한 발견 구조**로 유명지 쏠림을 구조적으로 차단

### F3. AI 여행지 추천 (`/api/recommend`) & 랜덤 여행지 추천
- **무엇**: 취향 태그(자연·미식·역사문화·휴식·축제) + 기분(활기차게/차분하게/지쳐서/자극이 필요한) + 자유 서술 → 추천 지역 1곳을 지도에서 자동 선택·포커스
- **가치**: "아무 데나 좋으니 새로운 곳" 니즈에 즉답. 인터페이스 분리로 **LLM 구현으로 무중단 교체 가능한 구조** 확보

### F4. 지역 상세 (`/region?sigCd=`)
- **무엇**: 지역 소개, 지표 스트립(관광 콘텐츠 수 / 맛집 수 / 착한가격업소 수 / 특산물 수), 유명한 것들, 추천 코스 카드(테마·소요시간·거리), 착한가격업소 표(업소명·메뉴·가격·주소), 카카오맵 길찾기 연동
- **가치**: 파편화된 정보를 한 화면으로 통합(P2 해결). **숫자 지표**로 "이 지역에 볼 게 있는가"를 즉시 판단하게 함



### F6. 내 코스 만들기 (`/course`)
- **무엇**: 좌측 후보 리스트(관광지/먹거리/착한 식당/특산물)에서 담아 우측 "나의 코스" 구성. 순서 편집, 총 장소 수·착한가격업소 포함 수 집계, 저장 → 완료 화면
- **가치**: 발견에서 끝나지 않고 **실행 가능한 결과물**로 연결(P4 해결). 서비스의 리텐션 훅

### F7. 위치 기반 부가 기능 (`geo.js`, `kakao-route.js`)
- **무엇**: 브라우저 위치 수집 → 출발지 자동 설정 후 카카오맵 길찾기 연결 (목적지만으로 길찾기), 코스 정해 지면 카카오맵 또는 네이버 지도에 경로 표시해서 제공
- 

### F8. 랜덤 여행지 추천

### F9. 여행 후기 + 공유 (`/my/courses`, `/review/*`, `/reviews`)
- **무엇**: 저장한 코스 목록(`/my/courses`) → 코스별 후기 작성(`/review/new`, 사진 최대 5장 + 줄글 + 공개 여부) → 후기 상세(`/review/{id}`, 공유 링크 대상) → 후기 피드(`/reviews`, 다른 사람의 후기 둘러보기)
- **가치**: **탐색 루프를 닫는 기능.** 지금까지의 동선은 "발견 → 코스 완성"에서 끝나 다시 방문할 이유가 없었다. 후기는 두 가지를 만든다 —
  1. **재방문 이유**: 다녀온 뒤 돌아와 기록을 남긴다
  2. **새로운 발견의 입력**: 남의 후기가 곧 "덜 알려진 지역"의 콘텐츠가 된다. 공공데이터가 채우지 못하는 **주관적 경험**을 사용자가 채우고, 후기 → 지역 상세 → 내 코스 만들기로 되돌아오는 순환이 생긴다
- **핵심 설계**: 후기 상세에서 항상 **"이 지역 보기" / "코스 만들기"로 되돌아가는 경로**를 노출한다. 후기는 읽고 끝나는 콘텐츠가 아니라 다음 여행의 진입점이다

### 4-1. 가치 요약
| 사용자 문제 | 대응 기능 | 전달 가치 |
|---|---|---|
| P1 어디로 갈지 모름 | F1, F2, F3, F8 | 목적지 없이 시작 가능한 탐색 |
| P2 정보 파편화 | F4 | 지역당 단일 통합 화면 |
| P3 가격 불확실 | F5 | 공식 데이터 기반 가격 신뢰 |
| P4 동선 수작업 | F6 | 담기 → 코스 완성 |
| P1 재발견 (반복 이용) | F9 | 남의 후기가 새 지역의 발견 입력이 됨 |

## 5. User Flow

### 5-1. 메인 플로우 (신규 사용자 · 목적지 미정)

```
[로그인 /]
   ↓
[회원가입 /signup] (신규만)
   ↓
[온보딩 /onboarding]  ── 건너뛰기 ──┐
   ① 여행지 유형  ② 분위기          │
   ↓                                ↓
[탐색 지도 /map] ←──────────────────┘
   │
   ├─ (A) 지도에서 시군구 직접 클릭
   │        ↓
   │     [우측 슬라이드 패널]
   │       · 지역 특산물
   │       · 착한가격업소 추천
   │       · 추천 반일 코스
   │
   └─ (B) "추천받기" 버튼
            ↓
        [AI 추천 모달]
          취향(다중) + 기분(단일) + 자유 서술
            ↓  POST /api/recommend
        [추천 지역 자동 선택 + 지도 포커스]
            ↓
        (A)의 패널로 합류
   ↓
[지역 상세 /region?sigCd=]
   · 지역 소개 / 지표 4종
   · 유명한 것들 · 먹거리
   · 추천 코스 카드 → "코스 자세히 보기" / "내 코스로 담기"
   · 착한가격업소 표 → "지도에서 보기"(카카오맵 길찾기)
   ↓
[내 코스 만들기 /course?sigCd=]
   좌: 관광지 / 먹거리 / 착한 식당 / 특산물 후보
   우: 나의 코스 (담기 · 순서 편집 · 집계)
   ↓  POST /course/save  (SavedCourse 로 DB 저장)
[저장 완료 /course/saved?courseId=]
   코스명 · 총 장소 수 · 착한가격업소 포함 수 · 경유지 목록
   ↓  "후기 쓰기"
─────────── 여기서부터 여행 후(後) 동선 ───────────
[내 코스 /my/courses]
   저장한 코스 카드 · 후기 있으면 "후기 보기", 없으면 "후기 쓰기"
   ↓
[후기 작성 /review/new?courseId=]
   사진 업로드(최대 5장) + 줄글 후기 + 공개 여부 선택
   ↓  POST /review
[후기 상세 /review/{id}]  ← 공유 링크가 가리키는 페이지
   사진 · 본문 · 다녀온 코스 · [링크 복사해 공유하기]
   ↓                              ↓
[이 지역 보기 /region]      [코스 만들기 /course]   ← 탐색 루프 복귀
```

### 5-1-2. 발견 루프 (다른 사람의 후기 → 새로운 지역)

```
[후기 피드 /reviews]
   공개된 후기 카드(대표 사진 · 지역 · 코스명 · 요약 · 작성자)
   ↓  카드 클릭
[후기 상세 /review/{id}]
   ↓  "이 지역 보기"
[지역 상세 /region?sigCd=]
   ↓
[내 코스 만들기 /course?sigCd=]  → 다시 저장 → 다시 후기
```

> 이 루프가 F9의 존재 이유다. 공공데이터는 "무엇이 있는지"를 알려주지만
> "가볼 만한지"는 다녀온 사람의 후기가 알려준다.

### 5-2. 보조 플로우
- **재방문 사용자**: 로그인 → `/map` 직접 진입 (온보딩 스킵)
- **추천 후보 없음**: `RecommendResult`가 null → 모달에 오류 표시, 지도 직접 탐색으로 유도
- **데이터 미적재 지역 클릭**: `dataReady=false` → "여행 정보는 아직 준비 중이에요" 빈 상태 UI 노출 (깨진 화면 방지)
- **위치 권한 거부**: 출발지 없이 목적지만으로 카카오맵 길찾기 실행
- **저장한 코스 없음**: `/my/courses` 빈 상태 → "지도로 가기"로 유도
- **공개된 후기 없음**: `/reviews` 빈 상태 → "내 코스에서 후기 쓰기"로 유도
- **비공개 후기**: 피드에 노출되지 않고 작성자만 링크로 접근
- **잘못된 접근**: 없는 코스 → `/my/courses`, 없는 후기 → `/reviews`, 남의 코스에 후기 쓰기 시도 → `/my/courses`

### 5-3. 화면 · 엔드포인트 정리
| 화면 | 경로 | 데이터 소스 |
|---|---|---|
| 로그인 / 회원가입 | `/`, `/signup` | — |
| 온보딩 | `/onboarding` | 클라이언트 |
| 탐색 지도 | `/map` | TopoJSON + 패널 API |
| 지역 패널 | `/region/panel` | DB 실데이터 |
| 지역 상세 | `/region?sigCd=` | DB 실데이터 |
| 내 코스 만들기 | `/course?sigCd=` | DB 실데이터 |
| 코스 저장 완료 | `/course/saved?courseId=` | SavedCourse (DB) |
| **내 코스 목록** | `/my/courses` | SavedCourse + Review (DB) |
| **후기 작성** | `/review/new?courseId=` | SavedCourse (DB) |
| **후기 저장** | `POST /review` | 사진 → 로컬 저장소, 본문 → Review |
| **후기 상세 (공유)** | `/review/{id}` | Review + SavedCourse (DB) |
| **후기 피드** | `/reviews` | 공개 Review 목록 (DB) |
| AI 추천 API | `POST /api/recommend` | RecommendService |

### 5-4. 사용자 식별 (현 단계 한계)
로그인은 아직 화면만 있고 인증이 없다(`login.js` 는 이동만 수행). 후기·코스에는 작성자가 필요하므로
**세션당 더미 사용자**를 만들어 작성자로 쓴다(`CurrentUserService` 인터페이스 → `SessionCurrentUserService`).
실제 인증 도입 시 이 인터페이스의 구현만 교체하면 되며, 후기 기능 자체는 수정하지 않는다.

## 6. 현재 진행 상황 (중간 피드백 시점)

**완료**
- 전국 시군구 지도 렌더링 및 클릭 인터랙션
- TourAPI 연동 적재 (관광지 / 음식 / 여행코스, 좌표 기반)
- 착한가격업소 CSV 적재 (시도+시군 → SIG_CD 매핑)
- 특산물 시드 적재
- 지역 패널·상세 DB 실데이터 전환 (더미 제거)
- 내 코스 만들기 DB 실데이터 전환
- AI 추천 API 골격 + 추천 모달 UI (교체 가능한 인터페이스 구조)
- **코스 서버 영속화** (`SavedCourse` + 경유지 — flash 임시 저장 제거)
- **여행 후기 기능 (F9)**: 내 코스 목록 / 후기 작성(사진 업로드) / 후기 상세 + 공유 / 후기 피드
- **후기 사진 업로드** (로컬 저장소 + 확장자 화이트리스트, `ImageStorage` 로 S3 교체 가능)

**진행/예정**
- `RecommendService`의 LLM 기반 구현 교체 (취향·기분·자유 서술 → 지역 매칭)
- 코스 동선 계산(소요시간·총 이동거리) — 현재 `-` 표시
- **실제 인증**: 현재는 세션 더미 사용자 → Spring Security + 회원가입/로그인 (`CurrentUserService` 교체)
- 데이터 커버리지 확대 (전국 시군구 적재율 향상)
- 개발용 H2 파일 DB → 운영 DB 전환 (설정 블록만 교체 가능하도록 분리 완료)

## 7. 성공 지표 (제안)

| 구분 | 지표 | 의미 |
|---|---|---|
| 핵심 | **탐색된 고유 시군구 수 / 세션** | "쏠림 해소"라는 문제 정의에 직결 |
| 핵심 | 비(非)유명 지역 상세 진입 비율 | 본 서비스 존재 이유의 직접 증명 |
| 전환 | 지역 상세 → 코스 저장 전환율 | 발견이 실행으로 이어지는가 |
| 기능 | AI 추천 사용률 및 추천 후 상세 진입률 | 추천 품질 대리 지표 |
| 차별점 | 착한가격업소 항목 클릭률 | 가격 신뢰 정보의 실효성 검증 |
| 루프 | 코스 저장 → 후기 작성 전환율 | 다녀와서 돌아오는가 (재방문) |
| 루프 | **후기 열람 → 그 지역 상세 진입률** | 후기가 새로운 발견으로 이어지는가 (F9의 핵심 가설) |
